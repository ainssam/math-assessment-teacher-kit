## 1. 이번 업데이트에서 달라진 점

이번 작업은 2학기 자료를 추가하면서 기존 1학기 자료의 표·채점기준·수치·제목·학년도 정보도 함께 정리한 누적 업데이트다. 교사가 평가 이름을 검색하는 데서 더 나아가, 같은 수학 주제나 성취기준을 다른 학교에서 어떻게 과제로 만들고 채점하는지 원문 근거를 비교할 수 있도록 자료와 접근 방법을 보완했다.

핵심 변화는 다음과 같다.

1. **공개 과제가 11,310개에서 21,416개로 늘었다.** 공개 학교·과목 사례는 5,061건에서 9,190건, 공개 과제가 있는 학교는 1,633개교에서 1,868개교로 늘었다. 공개 과제의 순증은 10,106개다.

### 3.2 공개 항목 수의 정확한 대조

기준선과 최종판의 항목 ID를 대조한 결과는 다음과 같다. 아래 여섯 행은 서로 겹치지 않는다.

| 기준선 공개 항목의 처리 또는 새 항목 | 개수 | 해석 |
| --- | ---: | --- |
| 기존 공개 유지·변경 없음 | 8,658 | 내용·기간·분류 메타데이터가 그대로 유지된 항목 |
| 기존 공개 유지·내용 변경 없이 기간 정정 | 1,088 | 기간만 정정한 1,055개와 기간·교육과정을 함께 정정한 33개 |
| 기존 공개 유지·분류 메타데이터만 변경 | 332 | 내용·기간 변경 없이 교육과정 등 사례 분류를 정정한 항목 |
| 기존 공개 유지·내용 변경 | 1,140 | 제목·본문·채점표·배점·비율 등의 변경. 일부는 기간·분류도 함께 변경 |
| 기존 공개 → 검토 상태 | 92 | 원문 근거에 따라 공개 목록에서 분리. 원래 행·ID·자료 보존 |
| 기준선에 없던 새 공개 ID | 10,198 | 최종판에서 새 ID로 공개된 항목 |

대조식은 다음과 같다.

```text
기존 공개 11,310 + 새 공개 ID 10,198 - 기존 공개의 검토 전환 92
= 최종 공개 21,416
순증 = 10,198 - 92 = 10,106
```

새 공개 ID 10,198개 중 10,177개는 기준선에 없던 출처에서 추가된 사례의 과제이며, 21개는 기존 사례에서 새로 분리·복구한 과제다. ‘기준선에 없던 출처’는 이 두 DB의 차이를 가리키며, 그 모든 원문을 마지막 정정 단계에서 새로 다운로드했다는 뜻은 아니다. 기존 검토 항목을 같은 ID로 공개 승격한 건은 이 대조에서 0개다. 기준선의 항목 ID는 모두 보존됐고, 사라진 기준선 항목 ID는 없다.

같은 공개 ID를 유지하며 교육과정·과목 그룹이 이동한 항목은 409개다. 전체에서는 유입 409개와 유출 409개가 상쇄되므로 순증 0개다. 이 409개는 위의 기존 공개 유지 범주에 이미 포함돼 있다. 과목별 증가를 해석할 때만 유입·유출을 별도로 반영하며 4.4절에서 식을 제시한다.

이 단계의 기준 DB는 `detail_table_repairs_v1.sqlite` → `v2.sqlite` → `v3.sqlite`로 각각 보존했다. 617개·1,032개·107개는 서로 다른 정정 축이며 같은 항목에 겹칠 수 있다. 기준선 11,310개와 비교한 변경 수와도 범위가 다르다.

### 7.2 v3→v4 원문 복구 단계 — 보존한 정정 이력

이 단계에서는 v3 DB의 저장 항목 45,857개를 보존한 채 새 파생 DB인 v4를 만들었다. 아래 표와 식은 최종 v5 수치가 아니라 앞선 정정 단계의 이력이다.

| 작업 | 건수 | 처리 방식 |
| --- | ---: | --- |
| 원문에서 새로 분리·복구한 실제 과제 | 384개 | 새 ID로 추가 |
| 기존 과제의 전체 원문 경계 보완 | 92개 | 기존 ID를 유지하며 본문·메타데이터·채점표 문맥을 재연결 |
| 독립 과제로 보기 어려운 추출 항목 정리 | 448개 | 원본 행 보존, 검토 상태로 구분. 직전 공개 425개와 이미 검토 상태였던 23개 포함 |
| 동일 원문 문맥의 채점표 연결 보완 | 469개 | 검증된 전체 과제 원문에 실제 채점기준이 있어 본문과 동일한 원문 문맥을 채점표에도 연결 |
| 파생 요약·방법·수치·제목 필드 정정 | 43필드 | 개요 27·방법 4·점수 4·시기 4·제목 2·원문 제목 2 |
| 이전 정정분의 순위·설계 태그·사례 캐시 갱신 | 1,737항목 | 앞선 세 정정 보고서의 실제 ID 합집합을 사용 |
| 공개 상태와 사례 표시의 불일치 재생성 | 16사례 | 공개 항목과 사례 요약·표시를 대조해 남은 과거 표시 불일치 보완 |

새 과제 384개를 더해 저장 항목은 46,241개가 됐다. 직전 공개 수와의 관계는 `21,506 + 384 - 425 = 21,465`다. 따라서 이 단계만 보면 공개 수는 41개 줄었지만, 실제 원문 과제는 384개를 새로 복구했고 독립 과제가 아닌 공개 조각을 425개 분리했다.

469개는 새로운 채점기준을 작성한 수가 아니다. 같은 원문의 완전한 과제 구간 안에 있는 실제 채점기준을 비교 화면에서도 읽을 수 있게 연결한 수다. 별도 채점표를 연결하지 못한 항목은 미확인 상태를 유지한다. 요약표만 확보한 과제에는 세부 수행 내용과 채점표를 그 구간에서 확인하지 못했다는 안내를 붙인다.

**384·92·448·469·43·1,737은 작업 축과 단위가 서로 다르다. 앞선 617·1,032·107, 뒤의 v5 작업 건수 또는 기준선 대비 새 공개 ID 10,198개에 더해 ‘총 몇 개를 추가했다’고 계산하지 않는다.**

### 7.3 v4→v5 후속 제목·경계·교육과정 정정

v4 이후 독립 QA에서 발견한 제목 경계 문제를 계기로 명시 표제, 행정·정의적 문장, 전체 형제 항목과 실제 과제를 다시 대조했다. 같은 원문 안에서 과목 연결이 잘못됐거나 실제 과제가 빠진 경우도 원문 구간을 복구했다. 동결 입력을 통합해 v4를 덮어쓰지 않는 v5를 만들었다.

| 작업 | 확정 건수 | 처리 방식 |
| --- | ---: | --- |
| 실제 과제의 새 ID 복구 | 87개 | 같은 원문의 평가영역·본문·실제 채점표를 근거로 새 과제를 추가 |
| 기존 ID의 전체 원문 구간 복구 | 36개 | ID를 유지하고 본문·채점표·경계와 확인한 수치 등을 보완 |
| 잘못 분리된 항목의 검토 전환·대체 연결 | 208개 | 직전 공개 138개와 이미 검토 상태였던 70개. 원본 행·ID 유지 |
| 기존 검토 ID의 실제 과제 복구·공개 전환 | 2개 | 위의 기존 ID 원문 복구 36개 안에 포함. 새 ID를 추가하지 않고 실제 평가 경계를 확인 |
| 원문에 명시된 제목 관련 필드 보완 | 1,416필드 | 제목 505·원문 제목 482·제목 근거 429. 1,416개의 새 과제라는 뜻이 아님 |
| 실제 원문 과목의 사례 복구 | 7사례 | 기존 출처·학교 근거를 유지한 새 사례. 새 학교 7개를 수집한 수가 아님 |
| 사례 분류 메타데이터 정정 | 919사례 | 인공지능 수학 분류 원장과 개별 원문 과목·교육과정·학년 정정 반영 |
| 사례 파생 캐시 대조 | 1,293사례 | 공개 과제명·태그·표시와 원문 항목 상태를 다시 맞춤 |
| 기존 정정분 파생값 재생성 | 3,168항목 | 이전 정정의 실제 항목 ID 기준으로 랭킹·설계 태그·캐시를 갱신 |
| 과목별 파생 집계 대조 | 35그룹 | 새 과목·교육과정 구분을 반영하고 오래된 coverage 8그룹의 집계를 해제 |

v4의 저장 항목 46,241개를 모두 보존하고 새 ID 87개를 더해 최종 저장 항목은 46,328개다. 이 단계의 공개 수는 `21,465 + 새 공개 ID 87 + 기존 검토 ID의 공개 복구 2 - 검토 전환 138 = 21,416`이다. 공개 목록에서 분리한 138개를 자료 삭제로 계산하지 않으며, 이미 검토 상태였던 70개를 공개 감소에 다시 빼지 않는다. 이 단계에서 공개 복구한 2개 ID는 초기 기준선에 없던 후속 항목이므로, 3.2절의 기준선→v5 대조에서는 새 공개 ID 범주에 들어간다. 두 비교의 ‘기존 검토’ 분모가 다르다.

v3→v4의 신규 ID 384개와 v4→v5의 신규 ID 87개는 서로 다른 단계에서 추가한 행이므로, v3 대비 저장 행 증가 471개와 일치한다. 그러나 이 471개를 기준선 대비 새 공개 ID 10,198개에 다시 더하지 않는다. 기존 ID 복구 92개와 36개, 채점표·수치·제목·캐시 정정은 같은 항목에 겹칠 수 있어 단순 합산한 ‘총 수정 과제 수’를 만들지 않는다.

## 8. 원문 그림과 확인 상태를 다루는 방식

### 8.1 원문 재현 범위

최종 공개 과제 중 **2,324개에 원문 그림 4,914개**를 연결했다. 이전 3차 운영판의 983개 항목·2,179개 자산에서 원문 확인 수단이 확대됐다. 이미지 수는 과제 수와 다르며, 본문과 채점표가 같은 완전 원문 문맥을 공유하면 같은 자산을 함께 참조한다. 최종 참조 자산은 총 987,288,040바이트로, 십진 단위 약 987MB다. 자산 파일의 크기를 교사가 한 번에 내려받는 화면 전송량으로 해석하지 않는다.

모든 공개 과제가 원문 그림을 갖춘 것은 아니다. 나머지 과제는 추출 표·발췌와 공식 원문 링크를 사용한다. 글꼴·수식·도형·지면 배치가 중요한 경우에는 공식 원문까지 함께 확인하는 절차를 유지한다.

원문 그림은 보존된 PDF 또는 원본 한글 문서의 렌더 결과에서 가져왔다. 원문의 수식을 새 이미지로 생성하거나 그럴듯한 수식으로 바꾸어 넣지 않았다. 본문·채점표 HTML의 압축 바이트 해시, 출처 문서 해시, 자산 파일 해시와 연결 범위를 기록했다.

원문 그림으로 발췌 전체를 확인한 경우와 일부 표만 대응하는 경우를 구분한다. 수식 텍스트가 원문 수식과 수학적으로 동등하다는 판정을 그림 연결 상태만으로 내리지 않는다. 글자층의 추출 순서가 복잡한 원문은 그림을 우선해 읽을 수 있도록 한다.

### 8.2 원문 자체의 오류와 빈 채점표

원문에서 다음과 같은 상태도 확인했다.

- 2학기 평가계획인데 평가시기에 6월이 남아 있는 경우
- 실제 과제는 공통수학2인데 설명에 공통수학1 교과서라는 문구가 남아 있는 경우
- 평가과제명은 독서·발표인데 상세 내용과 채점요소는 문제 풀이로 적힌 경우
- 성취기준 코드의 로마 숫자·과목 접두어·번호가 원문에서 누락되거나 맞지 않는 경우
- 채점표에 평가요소와 점수는 있지만 수준별 채점기준 서술 칸은 비어 있는 경우
- 총괄표와 세부표에서 평가명·점수 등의 표기가 다른 경우

이때 원문을 수정해 정상적인 계획처럼 만들지 않았다. `source_notes`에 원문 상태를 남기고, 원문 표제·숫자·코드는 확인한 대로 보존했다. 코드가 실제로 맞게 인쇄됐으나 PDF 문자 추출 순서 때문에 누락된 경우에는 ‘원문 그림에서 코드를 확인했다’는 근거를 별도로 남겼다. 원문 코드 자체의 오기와 변환 과정의 누락을 구분한 것이다.

본문·채점표 상세, 비교, 개인 AI 조회에서도 이 주의사항을 함께 전달한다. 빈 칸을 AI가 자동으로 채우거나 원문에 없는 루브릭을 학교의 실제 계획처럼 제시하지 않는다.

### 8.3 보류와 원본 보존

공개 보류는 기록 삭제가 아니다. 이전 DB, 원문, 출처 해시, 원래 ID와 검토 근거를 보존한다. 실제 과제가 복구되면 원래 잘못 분리됐던 조각과 대체 과제의 관계를 남긴다. 같은 과제의 본문을 보완할 때는 기존 ID를 재사용한 경우도 구분한다.

최종 통합은 기준 DB와 v4를 덮어쓰지 않고 새 v5 파일에서 진행했다. 직전 v4의 46,241개 항목과 이전 v3·기준선 DB의 항목 ID를 모두 보존했다. 자료가 검토 상태가 되면 공개 상세·비교 API에서 독립 과제로 제공하지 않도록 연결을 맞춘다.

## 9. 웹앱의 탐색·비교 흐름

### 9.1 전체 라이브러리

교육과정, 과목, 시도·시군구, 학년도·학기, 검색어를 조합해 찾는다. 수행평가명뿐 아니라 개요·방법·배점·성취기준·채점기준을 읽고 공식 출처를 대조하는 흐름을 유지했다. 검색 결과는 공개 경계를 통과한 자료이며, 필터 결과 수와 아카이브 전체 규모를 구분한다.

교육과정이 유보된 자료는 별도 상태로 표시한다. 원문 근거 항목이 함께 확인되는 순서로 정렬하며, 이는 과제 설계의 질이나 학교 순위를 나타내는 점수가 아니다.

### 9.2 주제 × 방법 탐색

생물 교과 앱의 개선 사례와 동국대 「수행평가 영역명 활용 가이드북」에서 참고한 두 축을 수학 과제에 맞춰 적용했다. 교사가 ‘무엇을 평가할 것인가’와 ‘학생이 어떻게 수행할 것인가’를 함께 좁히도록 구성했다.

| 축 | 현재 세부 선택지 |
| --- | --- |
| 주제 | 극한과 연속, 미분, 적분 |
| 방법 | 추론·증명, 그래프·시각화, 문항제작, 수학적 모델링, 자료분석, 계산·연산, 문제해결, 서술·논술, 발표·토론, 탐구, 과정평가 |
| 산출물 근거 | 보고서, 발표자료, 활동지·포트폴리오, 제작물 등의 표지 |

이 화면의 상세 두 축 색인은 **2026학년도 2학기·2022 개정 미적분Ⅰ** 범위다. 최종 v5에서 이 범위의 공개 색인 대상은 1,768개이며, 주제와 방법 양쪽의 근거가 확인된 항목은 599개다. 전 과목의 두 축 의미 분류가 완성됐다고 확대해 표현하지 않는다. 다른 과목은 전체 라이브러리, 전 과목 설계 유형 목록, 성취기준 비교를 이용한다.

카드의 ‘분류 근거’에서 원문 평가명·개요·평가방법·성취기준 중 어느 표현을 사용했는지 보여 준다. 한 과제에 여러 주제·방법이 붙을 수 있어 축별 숫자를 더해 전체 과제 수로 삼지 않는다. 규칙으로 확인한 활동 표지는 교사의 의미 해석과 수업 재설계를 돕는 출발점이다.

### 9.3 원문 비교와 교사 검토

원문 비교는 기존 기능을 유지하면서 정정된 데이터와 원문 그림·주의사항을 연결했다. 최대 4개 과제의 수행평가명, 개요, 방법, 시기, 만점, 반영 비율, 성취기준과 채점표를 나란히 읽을 수 있다. 공유 링크로 지정한 과제를 다시 열 수 있으며, 보류되었거나 불러오지 못한 과제는 상태를 안내한다.

교사 검토함은 과제 명료성, 수학적 사고, 과정 증거, 평가 정합성, 공정성, 실행 가능성의 여섯 기준을 사용한다. 채택·보류·제외 판단과 메모는 교사가 남긴다. 검토 기록은 해당 브라우저에 저장하며 자동 설계 품질 점수나 모델의 최종 판정을 섞지 않는다. 기존 비교함과 검토 기록의 저장 경로를 유지해 사용 중이던 기록을 보호한다.

## 10. 공식 성취기준 비교를 25개 교육과정·과목 조합으로 확대

### 10.1 제공 범위

| 교육과정 | 제공 과목 | 공식 성취기준 수 |
| --- | --- | ---: |
| 2022 개정 | 공통수학1·2, 기본수학1·2, 대수, 미적분Ⅰ·Ⅱ, 확률과 통계, 기하, 경제 수학, 인공지능 수학, 직무 수학, 수학과 문화, 실용 통계, 수학과제 탐구 | 15과목·254개 |
| 2015 개정 | 수학, 수학Ⅰ·Ⅱ, 미적분, 확률과 통계, 기하, 실용 수학, 경제 수학, 수학과제 탐구, 인공지능 수학 | 10과목·199개 |
| 합계 | 25개 교육과정·과목 조합 | 453개 |

초기 대수·미적분Ⅰ·확률과 통계의 54개 기준에서 24개 조합·440개로 넓힌 뒤, 2015 「인공지능 수학」 13개를 더해 25개 조합·453개를 등록했다. 기존 2015 기준 186개의 코드·문장과 2022 기준 254개는 그대로 보존했다. 같은 이름의 과목이라도 교육과정별로 기준 문장과 사례를 구분한다.

공식 문장은 교육부 고시의 별책 8 수학과 교육과정에서 구축하고 출처 URL·고시 명칭·원본 해시를 함께 보존했다. 2015 「인공지능 수학」은 [교육부 고시 제2020-236호](https://www.moe.go.kr/boardCnts/viewRenew.do?boardID=141&boardSeq=81884&lev=0)의 원본 HWP에서 추출한 13개를 사용한다. 이 과목의 출처만 해당 고시로 지정했고 나머지 2015 과목의 출처는 제2015-74호로 유지했다. 고시 PDF의 글꼴 때문에 깨진 기존 7개 문장의 수식은 원문 화면과 대조해 별도 검증한 전사를 사용한다.

원문 과목명이 통합수학Ⅰ·Ⅱ, 심화수학Ⅰ·Ⅱ, 상업수학인 자료는 실제 이름을 보존한다. 이런 원문 과목을 공식 비교 목록의 수학Ⅰ·Ⅱ, 공통수학1·2, 경제 수학 등으로 임의 대응하지 않는다. 25개 조합은 현재 구축한 공식 비교 기준의 범위이며, 원문에 등장하는 모든 학교 과목명이 여기에 자동 포함된다는 뜻이 아니다.

### 10.2 연결하는 근거와 비교 방식

교육과정·과목·학기·공식 성취기준을 선택하면 개별 수행평가에 해당 코드가 실제로 적힌 과제를 찾는다. 현재 연결 자료의 학년도는 2026학년도다. 두 과제의 교육과정·과목·코드가 모두 일치할 때 같은 기준의 공식 문장을 함께 표시하고 본문과 채점표를 비교한다.

이 기능은 같은 코드를 공유하는 과제를 찾는 기능이다. 과제 내용과 채점기준이 그 성취기준을 충분히 평가하는지까지 자동 확정하지 않는다. 코드가 없는 과제의 내용을 보고 코드를 임의로 추정해 넣지 않았고, 원문의 코드 오기를 편의상 다른 공식 코드로 연결하지 않았다.

여러 기준을 적은 과제는 여러 기준 목록에 나타날 수 있다. 기준별 연결 수를 합산해 전체 과제 수로 계산하지 않는다. 연결 과제 0개는 해당 과목 미개설이나 실제 수업 미실시를 뜻하지 않는다.

공식 근거, 수식 전사 검증과 API·화면 회귀 범위는 [성취기준 비교 안내](ACHIEVEMENT_STANDARD_COMPARISON.md)에 있다.

### 10.3 인공지능 수학 교육과정 분류의 후속 정정

기존 분류기는 「인공지능 수학」을 2022 개정에만 있는 과목으로 취급했다. 2015 교육과정에 제2020-236호로 추가된 같은 이름의 과목이 있어 이 전제를 수정했다. 새 분류기는 과목명과 `12인수` 코드 계열을 두 교육과정에 공통인 것으로 다룬다. 예전 추출 기록에 남아 있는 ‘2022 전용’ 힌트로 교육과정을 확정하지 않으며, 명확한 적용 학년 등 근거가 없거나 학년이 혼합돼 있으면 판별 유보로 남긴다.

같은 `[12인수01-01]`이라도 2015 개정 문장은 ‘인공지능의 발전에 기여한 역사적 사례에서 수학이 어떻게 활용되었는지를 이해한다.’이고, 2022 개정 문장은 ‘인공지능의 개념을 이해하고 학습 방식을 수학적으로 해석할 수 있다.’다. 따라서 코드가 같다는 이유만으로 같은 기준의 과제를 묶으면 서로 다른 교육과정의 과제가 섞일 수 있다.

후속 분류 명세는 기존 저장 사례 916건을 대상으로 작성했다. 보존된 v4 공개 항목의 추출본과 동결한 원문 복구 명세를 함께 사용해, 분류 검토의 공개 대상 1,172항목의 본문·채점표를 공식 문장과 대조했다. 원문 문장에 근거한 독립 검증도 수행했다. 이 검토 범위를 원래 v4에 있던 공개 AI 과제 수와 동일하게 사용하지 않는다. 결과는 다음과 같다.

| 후속 분류 명세 | 사례 수 | 해석 |
| --- | ---: | --- |
| 2015 개정 | 109 | 2015 공식 기준 문장 등 확인한 근거에 따른 분류 |
| 2022 개정 | 148 | 2022 공식 기준 문장 등 확인한 근거에 따른 분류 |
| 교육과정 판별 유보 | 659 | 어느 교육과정인지 확정할 원문 근거가 부족하거나 확정하기 어려움 |
| 합계 | 916 | 같은 대상 사례의 메타데이터 재검토 범위 |

유보 659사례 중 **동결한 원문 복구 명세를 반영한 분류 검토 시점에 190사례는 공개 대상 과제가 있었고, 469사례는 공개 대상 과제가 없었다.** 따라서 659사례 전체가 웹의 공개 목록에서 사라지거나 새로 추가되는 것으로 계산하지 않는다. 916건도 교육과정 값이 전부 변경됐다는 뜻이 아니라, 기존 분류 근거와 값을 다시 검토해 명세를 작성한 범위다.

독립 검증은 1,172항목의 본문·채점표 2,344부분을 원래 압축 데이터의 SHA-256과 연결하고, 두 교육과정에서 서로 구별되는 완전한 공식 문장의 일치를 다시 확인했다. 코드만으로 교육과정을 결정하지 않았다. 이 검증을 모든 원본 HWP·PDF를 처음부터 끝까지 새로 정독한 결과로 표현하지 않는다. 본문·채점표 원문 바이트를 바꾸지 않는 분류 메타데이터 정정이며, 별도로 실제 과제 경계를 복구한 경우와 구분한다.

**이 재분류는 새 학교나 새 원문을 수집해 늘어난 건수가 아니다.** 명세는 v5에 통합했으며, 최종 저장 AI 사례는 2015 109건·2022 148건·유보 659건이다. 실제 공개 과제가 있는 사례는 각각 109건·148건·189건이고, 공개 과제는 321개·394개·455개다. 검토 당시 유보 공개 190사례와 최종 공개 189사례의 차이는 후속 공개 경계 정정까지 반영한 결과이므로 두 시점의 분모를 혼동하지 않는다.

기준선과 최종판에서 같은 공개 ID를 유지한 AI 과제 409개가 분류 이동했고, 2015로 186개·유보로 223개 유입됐다. 4.4절의 과목별 대조식에 이를 포함했다. 이 이동을 자료 삭제·학교 미개설·새 수집 증가로 해석하지 않는다. 데이터 통합과 실제 운영 URL의 자료·과목 분류 응답을 함께 확인했다.

분류 원장은 `finish/final-title-followup/root-curriculum-ai-audit/v2/`의 명세·요약·사례별 근거이며, 독립 검증은 `finish/final-title-followup/final-input-ledger/independent-ai-curriculum-review.json`이다. 공식 기준 추가의 보존·재생성·45개 회귀 검사 결과는 `data/derived/math_standard_comparison_20261107/ai-2015-implementation-verification.json`에 기록했다.

## 11. 2022 개정 교육과정과 2028 대입 관점에서의 활용

이번 개선은 실제 과제를 ‘많이 모으는 것’에 더해, 수학 학습에서 확인할 사고와 증거를 읽을 수 있게 하는 방향이다. 2028 대입의 평가 기준이나 대학의 선호를 학교 평가계획 자료에서 추론하는 기능은 제공하지 않는다. 대입 정책에 관한 구체적인 판단이 필요하면 최신 공식 자료를 별도로 확인한다.

| 교사가 검토할 질문 | 이번 업데이트에서 활용할 수 있는 기능 |
| --- | --- |
| 같은 성취기준을 서로 다른 활동으로 구현할 수 있는가? | 공식 기준 문장과 같은 코드가 적힌 과제 비교 |
| 학생이 무엇을 해석·추론·설명·검토하는가? | 주제 × 방법 탐색, 원문 수행 내용, 수학적 사고 검토 항목 |
| 최종 결과 외에 수업 중 확인할 증거가 있는가? | 과정평가 표지, 포트폴리오·활동지 원문, 과정 증거 검토 |
| 과제와 채점기준이 같은 수학적 능력을 보는가? | 수행 내용과 전체 채점표의 나란히 읽기, 평가 정합성 검토 |
| AI를 사용하는 학생과 사용하지 않는 학생에게도 가능한가? | 원문 AI 사용 조건·source_notes 확인, 공정성 검토, 개인 AI 연구 질문 |
| 실제 차시·학급 규모·도구 조건에서 운영할 수 있는가? | 실행 가능성 검토와 수업 조건을 반영한 재설계 질문 |

개인 AI 연구 질문에는 문제 해석, 추론, 설명, 모델 검토, 과정 피드백을 실제 원문에서 확인하도록 했다. 새 제안은 학생이 수업 중 사고와 근거를 설명할 기회를 우선하고, 학생부용 문장이나 제출물 분량을 늘리는 제안과 구분한다.

AI 사용 조건은 원문에 명시된 경우만 확인한다. 언급이 없으면 미확인으로 남긴다. AI 사용 여부만으로 학생의 학습을 판단하지 않고, 학생이 조건과 풀이의 근거를 설명할 수 있는지 확인하는 재설계를 돕는다. 사례 몇 개로 전국 학교의 AI 허용·금지 비율을 만들지 않는다.

현재 제공하는 범위는 근거 탐색·원문 대조·교사 검토·재설계 지원이다. 평가계획이 실제로 그대로 실행됐는지, 학생의 학습효과가 어땠는지, 대학 입학에서 어떤 유불리가 있었는지를 검증한 자료로 사용하지 않는다.

## 12. 앱으로 설치하기

홈의 ‘앱으로 설치’에서 브라우저 설치 창 또는 기기별 홈 화면 추가 안내를 제공한다.

| 기기 | 설치 방법 |
| --- | --- |
| iPhone·iPad Safari | 공유 버튼 → 홈 화면에 추가 |
| Android Chrome | 메뉴 → 앱 설치 또는 홈 화면에 추가 |
| 컴퓨터 Chrome·Edge | 주소창 설치 아이콘 또는 브라우저 메뉴 → 앱 설치 |

앱 이름·아이콘·시작 주소·독립 실행 창을 위한 웹 앱 manifest와 서비스 워커를 추가했다. 브라우저에서 설치 지원이 다르거나 설치 창을 띄울 수 없는 경우에는 수동 안내를 보여 준다. 이미 독립 실행 중이면 설치 버튼을 다시 표시하지 않는다.

연결이 끊어졌을 때는 오프라인 안내 화면을 제공한다. 현재 서비스 워커는 안내 화면을 보관하는 구조이며, 전체 학교 데이터와 원문을 오프라인으로 내려받아 검색하는 기능까지 포함하지 않는다. 최신 사례 검색과 원문 조회에는 인터넷 연결이 필요하다. 교사 검토·비교 기록의 브라우저 저장과 전체 자료의 오프라인 보관을 구분한다.

## 13. 다른 선생님과 공유하기 위한 공개 자료

### 13.1 공개 MIT 저장소

공유 저장소는 [math-assessment-teacher-kit](https://github.com/ainssam/math-assessment-teacher-kit)이다. 공개 저장소 상태를 유지하고, 자체 소스코드·문서·가상 예제는 MIT 라이선스로 사용·수정·재배포할 수 있게 했다. 의존 패키지와 원문 자료의 권리는 각각의 이용 조건을 따른다.

교사가 내려받은 뒤 가상 예제를 생성해 화면과 API를 실행하고, 수집·추출·검증 과정을 단계별로 확인할 수 있도록 안내한다. Windows PowerShell을 기준으로 실행 명령을 제공하고, macOS·Linux의 명령 차이와 외장 드라이브 파일시스템 주의사항도 설명했다.

| 공개하는 자료 | 별도로 보존하는 자료 |
| --- | --- |
| 웹·API·수집 및 검증 코드 | 실제 학교 첨부 원문 |
| 실행 안내·처리 방법·질문 예시 | 전체 원문 추출문과 운영 DB |
| 가상 학교·과제·채점표 예제 | 학생 자료·교사의 개인 연구 결과 |
| 재현 절차·라이선스·출처 정책 | 개인 API 키·토큰·로그인 파일 |

교사용 시작 문서와 [수집·추출 실습](SCHOOLINFO_WORKFLOW.md)을 연결하고, 다른 교과로 바꿀 때 확인할 과목 경계·표·개인정보·공개 기준도 안내한다. 최종 변경분의 공개 커밋 식별자는 배포 확인란에 별도로 기록한다.

### 13.2 개인 AI에서 읽는 Python CLI

`scripts/math_assessment_research.py`를 통해 공개 API를 조회할 수 있다. Python 표준 라이브러리를 사용하며 도구 자체는 LLM 호출·개인 API 키·로그인·운영 DB가 필요하지 않다. 교사가 사용하는 개인 AI가 명령을 실행하거나 교사가 결과 JSON을 직접 첨부하는 흐름이다.

| 조회 명령 | 목적 |
| --- | --- |
| `meta` | 공개 아카이브 규모와 범위 확인 |
| `search` | 교육과정·과목·학년도·학기·지역·검색어로 사례 조회 |
| `item` | 실제 반환된 과제 ID로 본문·채점표·출처·그림 링크 조회 |
| `bundle` | 제한된 수의 과제를 실제로 읽고 비교용 JSON 작성 |
| `standards` | 공식 성취기준 문장과 코드 연결 과제 조회 |
| `references` | 유형별 참고 목록 조회 |

기본 조회 범위는 5개이며, 상한·offset·실제 읽은 과제 수·검색 일치 수·잘림·부분 실패를 구분해 반환한다. 검색의 사례 수와 bundle에서 읽은 과제 수를 혼동하지 않도록 출력 범위 설명을 추가했다. 원문 그림은 링크로 제공하며 AI가 그림을 실제로 읽었는지 따로 밝혀야 한다.

`research/prompts/`에는 다음 여덟 시작 질문을 제공한다.

1. 기하 사례 찾기
2. 같은 성취기준의 과제 비교
3. 공통수학 과목 간 활동 연결
4. 루브릭 읽기
5. 우리 수업 조건에 맞춘 재설계
6. AI 사용 조건과 학습 증거 검토
7. 자료 범위와 미검출 해석
8. 추론·설명 중심의 발전 방향과 2028 관점의 해석 경계

원문 사실·AI 해석·새 재설계 제안을 구분하고, 실제 조회한 과제 ID와 공식 출처를 붙이도록 연구 지침을 제공한다. 연구 결과는 `research/outputs/`에서 개인적으로 보관하며 공개 GitHub에 자동으로 올리지 않는다. 자세한 절차는 [개인 AI 연구 안내](AI_RESEARCH_GUIDE.md)에 있다.

### 13.3 MCP 여섯 조회 도구

MCP는 개인 AI가 검색·상세·채점표·공식 성취기준·원문 그림 조회 도구를 호출하는 경로다. 여섯 도구의 구현과 로컬 SDK·HTTP 계약 검증에 이어, 실제 운영 주소의 SDK 연결·도구 조회 검증도 완료했다. 서버가 별도 AI 모델을 대신 호출하거나 개인 AI 계정의 인증정보를 받는 구조가 아니다.

| 도구 | 하는 일 |
| --- | --- |
| `get_archive_scope` | 현재 공개 자료 규모·과목·학년도·학기와 조회 시각 확인 |
| `search_assessments` | 조건에 맞는 과제 검색과 반환 범위 확인 |
| `get_assessment_item` | 실제 과제 ID의 본문·채점표·수치·코드·source_notes·출처 확인 |
| `get_achievement_standards` | 공식 기준 목록 또는 선택 코드에 연결된 과제 조회 |
| `compare_assessments` | 실제 과제 ID 2~4개의 원문 근거 묶음 비교 |
| `get_original_preview` | 검증된 본문 또는 채점표 원문 그림 1개를 이미지로 조회 |

Streamable HTTP 방식의 [운영 MCP 주소](https://suhaeng-math.vercel.app/api/mcp)를 제공한다. 최종 배포의 실제 주소에서 여섯 도구 관련 119개 검사를 통과했고 실패는 0건이었다. 25개 조합·453개 공식 기준은 운영 SDK 응답과 등록 원장을 대조했다. 본문·채점표 원문 그림 응답의 실제 바이트 SHA도 일치했다.

서버 인증 없이 현재·이전 프로토콜 연결을 확인했으며 개인 인증 토큰은 사용하지 않았다. 이 검증은 공개 서버의 SDK 도구 호출이 성공했다는 뜻이다. 모든 교사의 웹 ChatGPT 계정에 자동 등록됐거나 모든 AI 제품에서 같은 연결 화면을 제공한다는 뜻으로 확대하지 않는다.

도구는 공개 자료의 읽기 전용 조회만 제공한다. 쓰기·삭제·원격 명령 실행·임의 URL·임의 로컬 파일 열기를 제공하지 않는다. 본문·HTML의 문자 상한, 검색 범위, 부분 실패, 보류 항목, 원문 주의사항을 응답에 포함한다. 그림 조회는 정해진 자산 경로의 출처·본문/채점표·자산 SHA 연결, MIME·서명·용량·통신 조건을 확인하고, 실패하면 명시적으로 알린다.

실제 연결 가능 여부는 사용하는 AI 도구와 계정·워크스페이스의 MCP 지원 범위에 따른다. 저장소나 서버에 개인 로그인 정보·토큰을 입력할 필요가 없으며, CLI 사용과 MCP 연결 성공을 같은 것으로 설명하지 않는다. 연결 방법과 검사 범위는 [MCP 연결 안내](MCP_CONNECTION.md)에 있다.

## 14. 검증 범위와 확인한 결과

### 14.1 자동 전수 점검과 원문 선별 검토

저장 자료 전체를 대상으로 하는 자동 검사와, 신호가 검출된 원문을 직접 대조하는 검토를 함께 사용했다.

| 검토 층 | 실제 수행한 범위 |
| --- | --- |
| 자료 무결성 | JSONL 행·중복·출처·상태, 원문/학교/과목 연결, DB 식별자·외래키·무결성 대조 |
| 저장 항목 자동 점검 | 전수 점검 시작 시 저장 항목 45,857개와 고유 출처 원문 11,166개를 검사 |
| 공개 표 렌더 검사 | 각 단계의 공개 항목을 대상으로 표·셀 충돌, 글자 손실, 이미지 연결 문제를 자동 점검 |
| 원문 대조 후보 | 글꼴·수식·셀 충돌 신호와 혼합 경계의 합집합 1,035항목, 평가계획 구간 복구 22사례 등에서 후속 검토 진행 |
| 제목·경계 추가 감사 | 긴 문장형 제목·수식 제목·행정 라벨·채점 질문·단원명·정의적 평가 및 형제 추출 항목을 추가 대조 |
| 잔여 표 구간 보완 | 추가 90항목 검토 묶음에서 56개 원문 구간 매칭과 34개 추가 원문 경계 대조 수행 |
| 최종 통합 검증 | 동결 입력·기존/신규 ID·본문/채점표 해시·대체 연결·이미지 파일 SHA·실효 공개 레지스트리 대조 |

검토 묶음 사이에는 중복이 있다. 이 표의 수를 합해 독립적인 검토 과제 수로 사용하지 않는다. 원문 구간 매칭, 그림 확인, 의미 검토도 같은 작업으로 세지 않는다.

자동으로 전체 자료의 오류 신호를 검사했다는 사실을, AI나 사람이 모든 학교의 모든 원문을 처음부터 끝까지 정독하고 수업의 의미·설계 품질까지 전수 판정했다는 뜻으로 확대하지 않는다. 학교 평가계획의 내용·실행·효과를 구분하고, 교사는 필요한 과제의 공식 원문을 다시 확인할 수 있다.

### 14.2 최종 통합 데이터와 코드 검증

- 최종 DB의 SHA-256은 `563a04c6a51a97284ceafb170dc6cf66d5e5e172daddfe01636b9a0abbdb8b3a`이며, SQLite 무결성·외래키·FTS를 확인했다.
- 직전 v4의 46,241항목을 전부 보존하고 신규 87항목을 더한 46,328항목을 확인했다. 기준선 ID 누락도 0개다.
- 최종 공개 21,416과제·9,190사례·1,868학교·고유 출처 6,165개를 DB에서 다시 집계했다.
- 승인 명세와 실제 46,328행의 기대값을 독립 대조했다. 새 과제 87·기존 복구 36·검토 전환 208·제목 관련 1,416필드·새 사례 7·사례 메타데이터 919의 허용 범위를 확인했다.
- 같은 ID에 다른 본문을 자동 덮어쓰는 충돌, 갱신·검토 전환 충돌, 다른 퇴역 항목으로 이어지는 잘못된 대체 링크를 검사했다. 기존 정상 과제와 보존 대상도 따로 확인했다.
- 동결 입력·참조 자산 해시 5,511건을 재검증했다. 최종 공개 미리보기 레지스트리 2,324항목과 원문 그림 4,914개의 출처·본문/채점표·범위·주의사항 연결을 확인했다.
- 랭킹은 저장 46,328항목 전체, 사례 캐시는 1,293사례, 과목 파생 집계는 35그룹을 독립 대조했다. 원문 정정이 과거 요약·검색·표시와 어긋나지 않도록 점검했고 오래된 coverage 8그룹을 집계에서 해제했다.
- 기준선→v5의 35개 과목별 증감식이 모두 성립했다. 같은 공개 ID의 분류 이동은 유입 409·유출 409로 전체 순증 0개임을 확인했다.
